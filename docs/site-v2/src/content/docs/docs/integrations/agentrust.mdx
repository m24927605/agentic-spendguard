<Aside type="caution" title="Planned, not yet verified">
  This page describes the fixture-only docs-first MVP currently in the
  repository and the target integration contract. The current MVP does not yet
  claim complete v1alpha1 signed-byte reconstruction, general artifact
  verification, or Linux hardening. SpendGuard does not yet make higher-tier trust,
  hardware-backed, or external connector claims.
</Aside>

SpendGuard already emits signed audit evidence for budget decisions and
outcomes. The AgenTrust integration will package that evidence for AgenTrust
tools without changing what SpendGuard claims:

- TRACE Level 0 software-only records for spend-control evidence.
- Agent Manifest artifact bindings for policy, tool catalog, evidence-bundle
  root, and build provenance hashes.
- Operator-supplied tool or build context is labeled separately when it is not
  present in signed SpendGuard evidence.
- No external connector output or gateway-integration claim in the v1alpha1
  target.

## Status

| Surface | Status | Claim boundary |
|---|---|---|
| Current repository MVP | Fixture-only smoke harness | CLI parsing, committed allow/deny fixtures, golden outputs, and make report scaffolding. Not full v1alpha1 verifier conformance. |
| AgenTrust integrations | Planned Community submission | Structure, README, manifest, links, and claims are verifiable. |
| TRACE | Planned Level 0 | Software-only signed evidence boundary. |
| Agent Manifest | Planned artifact binding | Hashes bind SpendGuard artifacts; this is not semantic proof of the SpendGuard contract DSL. |

## What gets exported

The exporter will start from a SpendGuard evidence bundle:

```text
spendguard-evidence/
  bundle.json
  decision.json
  outcome.json              # required for allow; absent for deny
  policy-bundle.json
  tool-catalog.json
  build-provenance.json
```

`decision.json` and, for allow paths, `outcome.json` come from canonical
SpendGuard audit events. The target exporter must verify SpendGuard signatures
before it emits any AgenTrust artifact. The current fixture MVP checks the two
checked-in bundles and emits golden outputs; it is not a general artifact
verifier.

The evidence bundle is not a trust root. Verification must use an
operator-controlled trust store; a public key included beside the evidence is
fixture metadata only.

## TRACE Level 0 mapping

| TRACE field | SpendGuard source |
|---|---|
| `subject` | Derived after signature verification from signed `tenant_id` and `run_id` as a SpendGuard SPIFFE-style URI. |
| `model` | Provider and model metadata from the decision/outcome event. |
| `runtime.platform` | `software-only`. |
| `runtime.measurement` | Hash of the evidence bundle. |
| `policy` | SpendGuard policy bundle hash and enforcement mode. |
| `data_class` | SpendGuard data classification, defaulting to `internal` when unset. |
| `build_provenance` | Release bundle, image digest, SBOM, or source commit digest. |
| `cnf` and `signature` | Generated by AgenTrust TRACE signing helpers. |

The target generated record must pass AgenTrust TRACE schema validation, local
TRACE signature verification, and the claimed Level 0 conformance tests. The
current fixture MVP byte-matches committed golden TRACE outputs signed with a
committed test key.

## Agent Manifest binding

The Agent Manifest output binds SpendGuard artifacts by hash:

| Manifest artifact | SpendGuard source |
|---|---|
| Policy bundle | SpendGuard contract bundle and schema bundle hashes. |
| Tool manifest | Endpoint catalog or framework tool catalog hash. |
| Model identity | Provider/model metadata from the audit evidence. |
| Decision trace | Evidence-bundle root and exported decision/outcome hashes. |
| Supply-chain provenance | Image digest, SBOM pointer, cosign signature, or release bundle digest. |

This is intentionally narrow. The first version does not introduce a
SpendGuard-specific Agent Manifest policy language.

## Current fixture command

The repository currently includes:

```bash
make verify-agentrust
```

For the fixture MVP, the command proves:

- Public CLI parsing and help output.
- The committed allow and deny fixtures still match approved hashes and bundle
  roots.
- Golden TRACE, Agent Manifest, SpendGuard artifact, and verification-report
  outputs are emitted for both fixtures.
- The private make harness is env-gated.

Deferred full conformance adds:

- Verify SpendGuard decision and outcome signatures.
- Generate and verify a TRACE Level 0 record.
- Generate an Agent Manifest binding.
- Fail negative tests for mutated evidence, wrong signing keys, missing TRACE
  signatures, and mismatched policy hashes.
- Add Linux path/output hardening and final package/public-surface guard scans.
- Prove at least one allow path and one deny path before any Verified tier
  request.

## Upstream integration manifest

The upstream Community submission should look like:

```yaml
name: Agentic SpendGuard
vendor: Agentic SpendGuard
integrates_with:
  - trace
  - agent-manifest
description: >-
  Maps SpendGuard signed spend-control audit events to TRACE Level 0
  software-only evidence and binds SpendGuard policy, tool-catalog,
  evidence-bundle root, and build-provenance hashes into Agent Manifest
  artifacts, with operator-supplied context labeled separately from signed
  evidence.
maintainer:
  github: m24927605
repository: https://github.com/m24927605/agentic-spendguard
license: Apache-2.0
tier: community
trace_conformance_level: 0
tested_against:
  agentrust-trace: "0.2.0"
  agent-manifest: "0.1.1"
```

Do not include non-v1alpha1 connector dependencies, extra `tested_against`
entries, or extra `integrates_with` entries in v1alpha1.
